# 🕷️ 爬虫与数据采集模块

独立的数据采集模块，与 stock_monitor 解耦。

> **历史沿革**：原先集中在 `apps/crawlers/` 下（xueqiu / eastmoney / iptv / news 混放）。
> 现已**拆平**到 `apps/` 下：`apps/xueqiu`、`apps/eastmoney`、`apps/iptv`、`apps/news`，
> `apps/crawlers/` 目录已删除。本文档由原 `apps/crawlers/README.md` 整理而来。

## ⚙️ 配置

统一配置在 **`apps/config.ini`**，由 `apps/config.py`（Python）读取；
Shell wrapper 脚本（`run_eastmoney.sh` / `run.sh`）用内置的 `get_ini_value` 直接读同一个 ini
（原 `apps/config.sh` 已删除——它导出的 12 个变量里只有 3 个被用到，且自带的 awk 解析器用的是正则匹配，易误命中）。

爬虫相关配置段按模块拆分（原 `[crawlers]` 段已取消）：

```ini
[xueqiu]
dir = /root/apps/xueqiu
data_dir = /data/xueqiu_data

[eastmoney]
dir = /root/apps/eastmoney
data_dir = /data/analyst_data
```

**路径解析规则**（`apps/config.py`）：ini 里写的是「容器内视角」绝对路径。

- 容器 / Linux 生产：原样使用（`/data` 是数据卷挂载点）
- Windows 本机开发：按 `[mount_point]` 映射到项目内
  （`/data` → `<项目根>/run`、`/var/log` → `<项目根>/logs`、`/root/apps` → `<项目根>`）

```ini
[mount_point]
; 值以 / 或盘符开头 → 本机绝对路径；否则 → 相对项目根；前缀最长优先
/data              = run
/var/log           = logs
/root/apps/stockdb = E:/work/code/stockdb
/root/apps         = .
```

支持 `${key}` 变量展开（引用同一段内的键），如 `[stockdb] pybao_dir = ${dir}/pybao`。

对应环境变量覆盖（`apps/config.py::get_path` 自动映射）：

| 配置项 | 环境变量 |
|---|---|
| `[xueqiu] dir` | `STOCK_MONITOR_XUEQIU_DIR` |
| `[xueqiu] data_dir` | `STOCK_MONITOR_XUEQIU_DATA_DIR` |
| `[eastmoney] dir` | `STOCK_MONITOR_EASTMONEY_DIR` |
| `[eastmoney] data_dir` | `STOCK_MONITOR_EASTMONEY_DATA_DIR` |

`run_xueqiu.sh` 额外识别 `XUEQIU_DATA_DIR`（优先级高于配置文件）。
两个 wrapper 脚本都会自算脚本目录（不依赖调用时的 cwd），日志写入
`[paths] log_dir`（`/data/logs`，随数据卷持久化）。

容器内还需保证 `PYTHONPATH` 含两个爬虫目录（`docker-compose.yml`、`configs/supervisord.conf` 已同步）：

```
PYTHONPATH=/root/apps/xueqiu:/root/apps/eastmoney:/root/apps
```

> 注：各脚本自身已做 `sys.path` 引导（把 `apps/` 加入路径），
> 所以脱离 `PYTHONPATH` 直接 `python apps/<mod>/<script>.py` 也能 import `config`。

## 🚀 快速开始

### 雪球爬虫

```bash
cd apps/xueqiu
bash run_xueqiu.sh                      # 运行脚本（自动重试/更新 cookies）
python3 xueqiu_scraper.py --mode=full   # 或直接运行
```

**功能**
- ✅ 自动登录雪球（保存 Cookies）
- ✅ 获取关注的大 V 文章
- ✅ 按作者分目录保存 HTML
- ✅ 自动去重、按月归档、生成更新摘要

**输出**：`/data/xueqiu_data/YYYYMMDD_HHMMSS/`

### 东方财富分析师爬虫

```bash
cd apps/eastmoney
bash run_eastmoney.sh                          # 运行脚本（内置采集组合，见脚本内 run_one 两行）
python3 eastmoney_analyst.py --list            # 列出可选的 slug（含中文对照）
python3 eastmoney_analyst.py -c electronics -p 2026_latest   # 命名参数（推荐）
python3 eastmoney_analyst.py -c all -p 12m
python3 eastmoney_analyst.py 0 0               # 兼容旧写法：<行业序号> <期间序号>
python3 eastmoney_analyst.py                   # 不带参数 → 交互式菜单
```

**参数一律用英文 slug**（便于在 shell 里书写，避免中文）：

- `-c/--category`：行业 slug，如 `electronics`、`nonferrous_metals`、`beauty_care`；默认 `all`
- `-p/--period`：期间 slug，见下表
- 也兼容中文名（`-c 电子`）与页面编码（`-c 270000`），但不推荐

**可选期间**（slug ↔ 中文 ↔ 页面按钮属性，取自真实页面 `#chart_type > li`）：

| slug | 中文（输出文件名用） | year | sort |
|---|---|---|---|
| `2026_latest` | 2026 最新排行 | 2026 | YEAR_YIELD |
| `latest_total` | 最新总排行 | 1 | INDEX_VALUE |
| `3m` | 3个月排行 | 3 | YIELD_3 |
| `6m` | 6个月排行 | 6 | YIELD_6 |
| `12m` | 12个月排行 | 12 | YIELD_12 |
| `2025_yearly` | 2025年度排行 | 2025 | YEAR_YIELD |

**功能**
- ✅ 采集分析师排名数据（Selenium 驱动 Chrome 无头模式）
- ✅ 按行业分类抓取（页面行业按钮带 `data-value` 编码，按编码精确点击，不再靠文本模糊匹配）
- ✅ 生成 HTML 报表 + Excel（「最新跟踪」/「历史跟踪」双工作表）

**输出**：`/data/analyst_data/processed_YYYYMMDD_HHMMSS/`（中间文件：列表页/详情页 HTML、CSV、`manifest.json`），
最终产物写在同级目录（文件名用**中文**便于阅读，参数用英文 slug）：

```
{类别}_{期间}_{YYYYMMDD}.xlsx     # 类别为「全部」时写作「全部类别」
{类别}_{期间}_{YYYYMMDD}.html
```

> 采集与后处理之间用 **`manifest.json`** 关联（记录 rank/name/详情页 URL 与文件路径），
> 后处理不再解析 HTML 文件名。

**报告内容与统计方法**（HTML 报告的「数据摘要」区块已内嵌以下说明）：

| 项 | 口径 |
|---|---|
| 数据来源 | 东方财富「分析师指数」列表页 → 逐个分析师详情页（Selenium 采集） |
| 记录范围 | 详情页两张表的全部数据行 —— `#news_table`（最新跟踪成分股）、`#history_table`（历史跟踪成分股） |
| 总记录数 | 两张表行数合计（每条 = 一位分析师 × 一只股票） |
| 分析师数量 | 本次成功提取到成份股的分析师**去重**计数 |
| 重点关注股票 | 只统计「最新跟踪」表；按被多少位**不同**分析师持有排序（同一分析师对同一股票只计一次），取前 20 |
| 价格列 | 平均/最高/最低成交价取自各分析师记录的「成交价格(前复权)」；「最新价格」取该股票第一条非空值 |

### IPTV / 新闻

见 `apps/iptv/`、`apps/news/`（各自独立，与爬虫主流程无关）。

## 🔧 故障排除

### Cookies 失效（雪球）

```bash
# 删除旧 Cookies 后重新登录（文件名是 .txt，不是 .json）
rm apps/xueqiu/xueqiu_cookies.txt
python3 apps/xueqiu/xueqiu_scraper.py
```

`run_xueqiu.sh` 在检测到 Cookies 失效时会自动从远端拉取并重试一次。

### ChromeDriver 版本不匹配

```bash
pip3 install webdriver-manager
python3 -c "from webdriver_manager.chrome import ChromeDriverManager; ChromeDriverManager().install()"
```

## ⚙️ 配置重构（2026-09-22，第二轮）

**问题**：`config.ini` 写的是「容器内视角」绝对路径，在 Windows 上 `/data` 被 Python 解析成 `E:\data`，
数据/日志落到了盘符根目录（实测 `E:\data` 累积 180 MB）。

**解决**：`apps/config.py` 增加平台化路径解析。

- `[mount_point]` 段**真正启用**（此前是死配置）：容器内路径 → 本机路径，
  值以 `/` 或盘符开头视为绝对路径，否则相对项目根，前缀最长优先。
- 新增 `${key}` 变量展开（同段内引用），如 `[stockdb] pybao_dir = ${dir}/pybao`。
- 非路径型配置（数字/布尔/URL/枚举）不受影响（不以 `/` 开头 → 原样返回）。

**配置段调整**：

- 新增 `[stockdb]`：`host` / `port` / `dir` / `pybao_dir` / `pool_offline_sqlite`
  （原混在 `[valuation]` 里，且是 Windows 绝对路径）。stockdb 跑在**宿主机** `<stockdb-host>:7899`，
  容器与 Windows 统一走该 IP。
- `[cache]` 并入 `[stock_monitor]`；`[valuation] cache_dir` / `pool_offline_sqlite` 也归入
  `[stock_monitor]` / `[stockdb]`；`[valuation]` 只保留方法论参数。
- 删除 `[web_app]`（`web_template_dir` / `web_static_dir` 全仓零引用）。
- `[paths] log_dir` 由 `/var/log` 改为 `/data/logs`：Python 日志本就在数据目录下（无需改），
  但 wrapper/cron 的日志原先写 `/var/log`（容器重建即丢），现统一到 `/data/logs`（持久化）。
- 删除 `apps/config.sh`（唯一消费者 `run_eastmoney.sh` 改为自算目录 + 直读 ini）。

**其它**：

- 修正 `sys.path` 引导：`eastmoney`/`xueqiu` 原先插入项目根（无用，靠容器 `PYTHONPATH` 兜底），
  改为插入 `apps/`（`config.py` 所在处）；`news`/`iptv` 新增同样的引导。
- `apps/iptv/download_m3u.py`、`apps/news/crawl_save_news.py` 去掉硬编码 `/data/...`，改走 `get_path`。
- 去除 `apps/iptv/download_m3u.py` 的 UTF-8 BOM。
- `docker-compose.yml` 挂载 `.../apps/stockdb:/root/apps/stockdb`（`pybao` 内含 `stockdb.pyd`，
  非 pip 包，必须存在）；`.gitignore` 忽略 `apps/stockdb/`。
- Dockerfile：移除 `COPY apps/config.sh`；cron 重定向由 `/var/log/cron/` 改为 `/data/logs/cron/`；
  `start_container.sh` 启动时 `mkdir -p /data/logs/cron`。
- **数据迁移**：`E:\data` → `<项目根>\run`（779 文件 / 180 MB，原目录封存为 `E:\data.moved-<时间戳>`）。

**验证**：Windows 上 `get_paths()` 全部落在 `<项目根>\run\...`；
`[stockdb] pybao_dir` → `E:\work\code\stockdb\pybao`；
13 个端点全 200 且 `success=true`（路由 44 个）；全部 `.sh` `bash -n` 通过且为 LF。
